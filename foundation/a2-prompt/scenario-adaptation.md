# 不同场景提示词适配技巧：办公/销售/设计/编程差异化指令

同样一个产品，你跟老板汇报、跟客户推销、在小红书种草，用的词和语气完全不同。AI 也是一样——同一个任务，不同场景需要不同的提示词策略。这篇帮你搞清楚「场景变了，提示词怎么跟着变」。

## 场景差异的本质

不同场景的核心差异在于三个维度：**目的、受众、约束**。

| 维度 | 办公汇报 | 销售转化 | 内容设计 | 技术开发 |
|------|---------|---------|---------|---------|
| 目的 | 信息传达、决策支持 | 促进行动、建立信任 | 引起兴趣、塑造品牌 | 解决问题、实现功能 |
| 受众 | 上级/同事（内部） | 客户/潜在客户（外部） | 大众/粉丝 | 自己/开发团队 |
| 约束 | 格式规范、信息准确 | 合规、不说谎、有说服力 | 平台调性、吸引力 | 逻辑正确、可执行 |
| 失败代价 | 领导不满意 | 丢单、损害品牌 | 没人看、被骂 | 出 bug、上线延期 |

## 一、办公汇报场景

### 核心原则：结论先行、数据说话、结构清晰

**提示词模板：**
```
你是一位[岗位]向[上级角色]汇报工作。

请帮我[整理/分析/总结]以下内容：
[粘贴原始内容]

要求：
- 第一句话直接说结论/结果
- 用数据支撑观点，不要空洞的描述
- 按重要性从高到低排列
- 如有问题，同时给出 2-3 个解决方案
- 控制在 [字数] 以内

格式：[要点列表 / 表格 / 结构化段落]
```

### 办公场景注意事项

| 要 | 不要 |
|-----|------|
| 指定汇报对象的级别和关注点 | 让 AI 自由发挥格式 |
| 提供完整的数据和事实 | 只给模糊的背景 |
| 明确汇报的目的是什么（要钱？要人？要决策？） | 不说目的，让 AI 猜 |

**实操对比：**

```
# 差的版本
帮我写个工作汇报，说一下项目进度

# 好的版本
你是一位项目经理，向公司 VP 汇报项目进展。
以下是本周的关键事件：
- 后端接口开发完成 80%，预计周五联调
- UI 设计稿客户已确认，无修改意见
- 发现一个风险：第三方支付接口审核可能延迟 1-2 周

请写一份简要汇报（200 字内），结论先行，最后附风险应对建议。
用要点列表格式。
```

## 二、销售与商务场景

### 核心原则：站在客户角度、有理有据、推动行动

**提示词模板：**
```
你是一位有[X]年经验的[行业]销售顾问。

客户信息：
- 行业/规模：[描述]
- 当前痛点：[已知痛点]
- 决策阶段：[初步了解 / 方案比较 / 即将决策]
- 我们的优势：[列出 2-3 点]

请帮我[写开发信 / 准备演示话术 / 处理异议 / 做报价说明]。

要求：
- 从客户关心的角度切入，不是从我们的功能切入
- 用具体场景和案例代替抽象描述
- 语气 [专业/友好/不卑不亢]
- 结尾有明确的下一步行动引导
- 不夸大、不虚构、不用销售套话
```

### 销售场景注意事项

| 要 | 不要 |
|-----|------|
| 告诉 AI 客户的决策阶段 | 没有上下文就让它写话术 |
| 指定语气——是主动还是温和 | 让 AI 用模板化的"尊敬的客户" |
| 提供真实的差异化优势 | 让 AI 自己编造卖点 |
| 明确不能说什么（价格底线等） | 不设边界 |

**实操对比：**

```
# 差的版本
帮我写一封给客户的邮件，推销我们的 CRM 系统

# 好的版本
你是一位企业软件销售，风格专业但不油腻。

客户：一家 50 人的贸易公司老板，目前用 Excel 管客户，经常跟丢单。
我们产品：轻量 CRM，核心优势是"手机端就能用，5 分钟上手"。
目标：让客户愿意约 15 分钟的产品演示。

请写一封开发邮件：
- 开头用客户可能的痛点场景切入（不是自我介绍）
- 中间用 1 个具体场景说明我们的价值
- 结尾约 15 分钟电话演示
- 不超过 200 字，不要加任何 emoji
```

## 三、内容创作与设计场景

### 核心原则：抓眼球、有个性、符合平台调性

**提示词模板：**
```
你是一位[平台]内容创作者，粉丝画像是[受众描述]。

请帮我创作[图文/视频脚本/海报文案]，主题是[主题]。

我的风格参考：
[粘贴 1-2 段你满意的历史内容，或描述风格]

平台要求：
- [小红书：标题要有数字和痛点词，正文分段短]
- [抖音：前 3 秒要留人，节奏快]
- [公众号：有深度，可读性强]

要求：
- [具体要求 1]
- [具体要求 2]
- 不要用 AI 味的表达（如"让我们一起来探索"）
```

### 内容场景注意事项

| 要 | 不要 |
|-----|------|
| 指定具体平台和内容形式 | 只说"写个文案" |
| 给风格参考（示例 > 描述） | 说"写得有趣一点" |
| 说明发布时间和频率（影响内容策略） | 忽略平台特性 |
| 提供目标数据（阅读量/互动率目标） | 没有衡量标准 |

**不同平台调性速查：**

| 平台 | 标题特点 | 正文字数 | 语气 |
|------|---------|---------|------|
| 小红书 | 数字+痛点+emoji | 300-800 | 闺蜜安利感 |
| 抖音/视频号 | 前 3 秒决定生死 | 脚本 500 字内 | 快节奏、口语化 |
| 公众号 | 痛点/悬念/反常识 | 1500-3000 | 有深度、有观点 |
| 朋友圈 | 像朋友说话 | 100 以内 | 真实、不装 |
| B 站 | 标题党但要真诚 | 弹幕互动设计 | 有梗、有态度 |

## 四、编程与技术场景

### 核心原则：精确描述、提供上下文、明确验收标准

**提示词模板：**
```
你是一位[技术栈]高级开发工程师。

任务：[精确描述要实现什么功能/修复什么 bug]

技术环境：
- 语言/框架：[如 Python 3.11 + Django]
- 数据库：[如 PostgreSQL 14]
- 其他依赖：[如 Redis, Celery]

现有代码（如适用）：
[粘贴相关代码]

要求：
- 遵循 [代码规范/风格]
- 包含错误处理
- 关键逻辑加中文注释
- 如有多种方案，说明各自优劣并推荐一种

输出格式：
[完整代码 / 代码片段+说明 / 分步骤指导]
```

### 技术场景注意事项

| 要 | 不要 |
|-----|------|
| 提供完整的技术栈和版本号 | 只说"用 Python 写个功能" |
| 粘贴相关代码或错误日志 | 让 AI 猜你的代码结构 |
| 说明业务背景（帮 AI 理解为什么这么写） | 只描述技术需求不描述业务 |
| 指定性能/安全要求 | 忽略边界情况 |

**实操对比：**

```
# 差的版本
帮我写一个用户登录功能

# 好的版本
你是一位 Python 后端高级开发。

请用 FastAPI 实现用户登录接口。

技术栈：Python 3.11, FastAPI 0.104, PostgreSQL, JWT 认证
要求：
- 支持邮箱+密码登录
- 密码用 bcrypt 加密存储
- 登录成功返回 JWT token（有效期 24 小时）
- 连续 5 次失败锁定 30 分钟
- 包含完整的错误处理和参数校验

输出：完整的代码文件 + 简要说明
```

## 跨场景通用法则

不管什么场景，这些法则都适用：

| 法则 | 说明 |
|------|------|
| 目的明确 | 先想清楚"让 AI 产出的这个东西最终要给谁看、解决什么问题" |
| 受众画像 | 告诉 AI 读者是谁，比告诉 AI 写什么更重要 |
| 示例优于描述 | 风格、格式、调性，给一个示例胜过描述 100 字 |
| 禁忌要写 | "不要什么"比"要什么"更容易被 AI 执行 |
| 迭代不重写 | 第一次不好不要推翻重来，精准修改即可 |

## 小结

场景变了，提示词的侧重点也要变：

- **办公汇报** → 结论先行、数据支撑、格式规范
- **销售转化** → 客户视角、场景化、推动行动
- **内容创作** → 平台调性、风格一致、抓眼球
- **技术开发** → 精确描述、完整上下文、明确验收标准

核心心法：**先想清楚"给谁看、要什么效果"，再写提示词。**
